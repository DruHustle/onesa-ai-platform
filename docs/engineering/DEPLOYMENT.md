Frontend staging explicitly selects Preview before dispatch. Provider source,
project and target readback and the single durable create budget remain mandatory.
Source changes require fresh reviewed installation and qualification.

Runtime preservation snapshots wait a bounded time for temporary Docker clients
to finish. Every persistent and unknown workload remains in the snapshot; actual
identity changes, missing services and incomplete observations still block release.

Static artifact verification accepts generated Next.js catch-all filenames while
retaining canonical path, response-size and byte-digest checks. A verifier fix
requires new source qualification and commissioning; failed contexts stay consumed.

Qualification probes include and verify their required source resources before
hosted work. Failed or partial UI evidence remains unqualified.

Detailed operational instructions are maintained in protected Engineering Docs.
This public source is a reference page, not a deployment or recovery runbook.

## Oracle owner-run evidence bridge

The new `scripts/release/oracle_owner.py` adapter preserves owner-run receipts
with workflow run ID `0` and genuine CI run references. It requires a separately
commissioned, pinned external verifier and owner-controlled signing custody.
Repository code or an unsigned JSON file supplies no release authority.
The protected guide contains installation, qualification and recovery instructions;
source implementation alone does not establish commissioning or deployment.

Canonical application source is a separate, explicit schema-2 installation option.
It binds the `onesa-ug` repository's numeric identity, exact `main` commit and root
tree to the `platform` product path/tree and both pinned hosted source-artifact
archives. The application tar remains product-relative. Source verification is
read-only evidence and never commissions a component or authorizes a release.
Only the existing literal application profile sets are supported; public/internal
Docs remain under their existing independent source and publication contracts.

The canonical API and its Preview frontend must use the same complete source
identity. Their configuration, artifact, component and provider identities remain
separate. The credential-free build uses the product-relative application root,
then seals the canonical provider root into its deployment metadata. Provider
readback and the pinned deployment transport check that full source identity.

A retained legacy API or frontend is only a read-only dependency. Its original
commissioned verifier bytes, trust anchor, public key, policy and accepted signed
chain must remain available and unrevoked. The new reader neither executes that
controller nor writes, relabels, renews or transfers its records. Missing original
custody or an unsupported rollback blocks the transition. Actual installation,
commissioning, protected recovery evidence and hosted acceptance remain required.

The AI component runners, reviewed installer and credential-free prebuilt builder
now accompany the adapter. They keep candidate application bytes separate from
commissioned verification tools and record deployment intent before a provider
request. Source identity readback, additive-schema rollback, scoped synthetic
workflow checks and coordinated encrypted database/file recovery remain gates.
Their presence in source does not mean a host installation, qualification or
production deployment has completed. The protected evidence index records each
observed outcome separately.

The pinned uploader distinguishes a complete provider missing-file rejection from
an uncertain create response. Only the former permits one identical file-upload
continuation; lost, ambiguous or successful responses remain inspect-only.
Credential-free tests exercise the real pinned client against a loopback fixture.


The owner frontend runner binds and verifies the specifically named server API
origin independently of Git branch metadata. Manual prebuilt deployment must not
fall back to a loopback backend when branch-only variables are absent. The protected
guide contains the exact source-bound routing configuration and current records.

Before consuming a qualification context, the AI runner now checks the actual pinned
vendor CLI with a read-only authentication request. Expiring custody must contain a
coherent, current owner CLI snapshot; replacing only its token can leave incompatible
expiry metadata. This check grants no release authority. Early runner diagnostics
are retained without credentials or an additional deployment attempt allowance.

Migration custody recognizes the existing runtime system CA reference while retaining
the explicit pinned CA for supplied owner connections. It does not alter runtime
credentials, certificate settings, database roles or migration authorization.
The read-only probe measures TLS on its actual client connection; a provider's
internal backend connection does not establish the external client's TLS state.
