# Industrial Investigation — evaluation and design-partner preparation

Internal product material. Synthetic demonstration only. No customer/factory data,
connected machinery, external work-order dispatch or operational diagnosis. The
company remains pre-commercial. This document prepares feedback; it reports no
customer interview, engineer acceptance, price, signed pilot or business benefit.

## Five-minute walkthrough

| Time | Action | What to assess |
| --- | --- | --- |
| 0:00–0:40 | Sign in through the maintained isolated demo entry; select Demonstration press, reference scenario and 09:00–10:00 UTC on 20 October 2026. | Approved account, correct environment, synthetic label and selection. |
| 0:40–1:20 | Review source coverage, freshness and applicable reference versions. | Sparse samples are not continuous coverage; identify gaps before explanation. |
| 1:20–2:00 | Inspect calculated facts and source timeline. | Three stops, 720 seconds / 12 minutes; event count differs from downtime episodes. Cause remains unknown. |
| 2:00–3:00 | Run only within an approved generation allowance; otherwise reopen an existing result with its original date/source. | Separate observed facts, possible explanations and abstention. Resolve every citation and check whether it actually supports the hypothesis. |
| 3:00–4:20 | Explicitly create/edit/save an internal draft, record a self-review decision, then reopen it. | Failed saves retain entries; edited drafts invalidate the current review; acceptance is not machinery authority. |
| 4:20–5:00 | Download the synthetic evidence and compare it with the saved revision. Select the open-event scenario. | Incomplete duration is a lower bound. Useful abstention identifies evidence needed next; no invented root cause or full total. |

A model timeout, quota refusal, malformed result or invalid citation is a failed
attempt, not an explanation. Keep its facts/error and record the failure. Cancellation
ends the application operation; provider computation may still continue. Do not retry
outside the stated experiment. Explain the mock label if using local fixtures.

## Frozen evaluation scope

`onesa-industrial-evaluation-v1.1.0` lives in the existing backend fixture area.
Run `./.venv/bin/python scripts/evaluate_industrial.py --output <new-private-file>`.
With an isolated loopback database named `_test`, add `--database` to execute API/
lifecycle tests. Never point the harness at staging/production records. CI executes
the offline evaluator; native backend CI supplies its own isolated database.

Report deterministic facts, structural source/citation validity, human-rated support,
unauthorized access, latency/usage, cost and baseline comparisons separately. Visible
held-out regressions demonstrate specified behavior, not universal generalization.
The unsupported-causal-claim case intentionally passes identity/quotation checks:
an engineer must reject its unsupported cause and operating instruction. Neither a
regex nor the same model supplies independent semantic assurance.

## Human evaluation worksheet

Reviewer name/role: **Not recorded**. Date: **Not recorded**. Relevant equipment/domain
experience: **Not recorded**. Source/deployment and evidence export: **Not recorded**.

For each case, record the case ID, expected facts, visible coverage, response outcome,
source support, missing evidence, draft corrections, elapsed task time and failure.
Use **0 = incorrect/unsafe**, **1 = partly useful with material correction**,
**2 = acceptable within stated synthetic scope**, or **N/A = not observed**.
Leave the ratings empty until an actual maintenance, reliability or production
engineer performs the task.

| Criterion | Required acceptance evidence | Rating / correction |
| --- | --- | --- |
| Facts | Correct asset/window, interval union, units, versions and known lower bound; no fabricated complete total. | Unfilled |
| Source support | Each cited source is permitted/current and its actual meaning supports the claim; a matching quote alone is insufficient. | Unfilled |
| Unsupported conclusions | Reject established-cause claims, invented certainty, wrong-asset evidence and instructions unsupported by the record. | Unfilled |
| Useful abstention | State what is unknown and the specific additional evidence a human should obtain; no absence inference from missing data. | Unfilled |
| Clarity and limits | Facts, hypotheses, mock/real outcome, coverage and self-review status remain distinguishable. | Unfilled |
| Draft usefulness | Relevant, editable internal investigation draft; no automatic dispatch or equipment action. | Unfilled |
| Corrections and access | Failures retain work, revisions reconcile, other accounts cannot read/change the result, revoked access is denied. | Unfilled |

Any wrong-asset disclosure, fabricated source, unsupported certainty, unsafe instruction
or incorrect factual total is a blocking finding for the evaluated case. Record human
acceptance separately from software test success and owner self-review. Do not delete
failed observations or tune held-out expected answers to a model response.

## Comparison protocol — not yet run

An engineer and a named general-assistant baseline should receive the same frozen,
rights-cleared synthetic information, asset/window and task. Record tools, model/config,
repetitions, token ceilings, failures, retries, time to a useful reviewed draft and
required corrections before comparing. Do not infer savings from one model latency.
Cost per useful task requires actual provider pricing/usage and an observed useful
completion denominator; until then it is **null / NOT_OBSERVED**. Human ratings and
comparative benefit are **NOT_RUN**.

## Discovery guide — prepare only; do not send

1. Walk through the last repeated-stop investigation: trigger, decisions, elapsed
   effort and how effort was measured. Do not request actual factory files yet.
2. Identify event logs, time series, manuals, versions, quality gaps, ownership,
   permission requirements and time lost obtaining the evidence.
3. Who investigates, reviews and authorizes action? What belongs in a useful draft,
   and what incorrect conclusion would cause harm?
4. Which tools already support the workflow? Who owns procurement, security review,
   support and the decision to run a limited evaluation?
5. Agree one measurable evaluation workflow and a stopping condition before any
   real-data access. Record interview findings only after the conversation occurs.

## Access and release procedure

Use the exact maintained isolated-demo entry and expiry in the restricted release
receipt; do not assume an old Preview or grant still works. An ordinary AI account
is not a demo invitation or Engineering Docs membership. Request/approve access through
the existing account/invitation flow. An operator records grant expiry and revocation;
no password reset is required for routine grant renewal. Changes to grants or stable
DNS/aliases require their specific owner authority. Never post credentials or share
an owner's session with a design partner.

V1.1 source, isolated demo API/frontend and normal production have independent
identities. Keep production disabled for Industrial until its separate activation
is qualified. Existing approved Docs access and Robot safety/history are unaffected;
this package does not reopen those completed acceptances or supply missing privacy,
real-data rights, processor, retention or commercial decisions.
